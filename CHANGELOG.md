# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). The rules for choosing a version, the commit message
convention and the release steps are in [docs/VERSIONING.md](docs/VERSIONING.md).

> **About versions before 1.1.0.** The repository had no tags and `package.json` stayed at `1.0.0` throughout, so
> every version below 1.1.0 was **reconstructed from the git history on 2026-10-24**. Where the author labeled a
> commit "version 0.x", that label is kept. Later work is grouped by theme. Each entry lists the commits it covers;
> `docs/VERSIONING.md` has the `git tag` commands to make the reconstruction official.

## [1.1.0] - 2026-10-24

Live theme editing in development. Production output is byte-identical to 1.0.0.

### Added
- **Theme lab HUD** (dev only): a `<theme-lab>` panel with tabs for Colors, Type, Shape, Motion and Layout. It edits
  the theme live through sliders with exact number fields, color pickers with OKLCH tuning, validated text fields for
  CSS values (shadows, easing, fluid sizes) and an easing preview.
- Live **contrast checking** for every color in both modes, a list of failing checks, and a one-click **Fix** that
  adjusts lightness to the nearest passing value.
- **Undo/redo**, hold-to-**compare** with the saved preset, **reset**, drafts that survive a reload, and a panel that
  docks left or right. Closes with Esc; tabs use arrow keys.
- **Save as preset**: writes `src/theme/presets/<name>.ts`. The built-in `ink` and `sand` presets are read-only, so
  edits to them are saved under a new name; user presets can be updated in place. **Copy code** is the fallback.
- Dev-only endpoint `POST /__theme-lab/save` (Astro integration `src/integrations/theme-lab.ts`). It accepts only
  same-origin requests from the machine running the dev server, rebuilds the payload from the `ink` shape, pattern-checks
  every string, refuses presets that fail contrast, and writes atomically.
- `src/theme/presets/_registry.ts`, generated by `npm run presets:sync`, so adding a preset is "add a file".
  `npm run check:theme` fails when it is out of date.
- `npm test`: unit tests for color math, the serializer, the input guard, the save endpoint and the registry (10 tests,
  Node's built-in test runner). CI runs them.
- `src/theme/vars.ts`, `color.ts`, `serialize.ts`, `lab-guard.ts`, `lab-server.ts`, `registry-sync.ts`, `builtin.ts`.
- `CHANGELOG.md` and `docs/VERSIONING.md`.

### Changed
- CSS variable generation moved from `css.ts` into the asset-free `vars.ts`, so the build and the browser preview use
  one generator and cannot drift.
- `src/theme/index.ts` reads presets from the generated registry; `PresetName` stays a literal union.
- `check:theme` also verifies that each preset's `name` matches its file name.
- `package.json` version bumped to 1.1.0; the deploy workflow also runs `npm test`.
- `README.md` and `docs/THEMING.md` updated for the Theme lab, preset workflow, scripts and versioning.

### Fixed
- `docs/THEMING.md` said to edit `activePreset`; the constant is `DEFAULT_PRESET`.
- `public/images/projects/README.txt` pointed at `src/data/content.js`, which is now `content.ts`.

### Security
- The save endpoint writes source files, and `astro dev --host` is reachable from the local network. It therefore
  refuses non-loopback clients, non-local `Host` headers, missing or foreign `Origin`, and requests without the custom
  `X-Theme-Lab` header. It is registered only by `astro dev`, and the panel's code is not part of `astro build`.

## [1.0.0] - 2026-10-24

First stable baseline: a theme-driven site with guardrails. _Commits `a5a558a`, `bb86f38`._

### Added
- **Theme system** in `src/theme/`: typed `Theme` schema, the `ink` and `sand` presets, a generator that emits custom
  properties, `@font-face` rules, preload tags, `theme-color` and the favicon, and a `PORTFOLIO_THEME` build switch.
- `src/config/site.config.ts`: section order and visibility, hero (`split`/`centered`) and work (`grid`/`list`)
  variants, optional features.
- **Guardrails**: WCAG contrast check that stops a failing production build, `npm run check:theme`, Stylelint rules
  that ban raw colors, radii, font sizes and durations in SCSS (`npm run lint:css`), and CI steps for both.
- First, small dev-only Theme lab: preset, hero and work switchers.
- `docs/THEMING.md`.

### Changed
- Styles read theme tokens instead of fixed values; font declarations moved into the theme.

### Removed
- `package-lock.json` is no longer tracked.

## [0.9.0] - 2026-10-18

The structural refactor, labeled "Phase 1" to "Phase 5C" in the commits. _Commits `34cd8dc` to `6797a06`._

### Added
- Build-time content validation in `src/data/content.ts`: duplicate project and discipline IDs, English/Persian
  parity, missing or orphaned `workShared` records, invalid related-project references.
- `docs/content-launch-checklist.md`.

### Changed
- `Page.astro` split into section components (hero, skills, process, work, resume, contact), dialog components and a
  navigation component.
- Client behavior extracted into `src/scripts/`: scroll and section tracking, modal and menu controller, theme
  controller, copy controller, performance controller, visual effects.
- README rewritten around the content source of truth.

### Removed
- The leftover `src/data/site.js`, superseded by `content.ts`.
